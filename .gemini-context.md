## 🏗️ Architectural Foundations

### 1. Database & Ledger Consistency
- **Engine**: SQLite 3 with WAL mode enabled (`db.js`).
- **Safety**: Connection-level `PRAGMA foreign_keys = ON;` is enforced.
- **Concurrency**: `PRAGMA busy_timeout = 5000;` prevents database locks during simultaneous STK Push callbacks and client sync operations.
- **Ledger Constraints**: Double-entry general ledger records use a unique index `idx_ledger_ref_type_id` on `(ref_type, ref_id)` to automatically reject duplicate webhook payloads.
- **Transactions**: All ledger operations are wrapped in atomic SQL transactions (`BEGIN TRANSACTION ... COMMIT/ROLLBACK`).

### 2. Network & CORS Subnets
- The production server is hosted on OCI Ampere (ARM64) at `100.68.227.114:8089` on a private Tailscale network.
- **CORS Config**: Express CORS middleware in `server.js` allows loopback, LAN subnets (`192.168.x.x` and `10.x.x.x`), and the **Tailscale CGNAT range** (`100.64.0.0/10` which maps to `100.64.0.0–100.127.255.255`).

### 3. Biological Mechanics
- **Flock Split**: Flocks are split into separate baseline counts for `hens` and `roosters` (to compute lay rate against active laying hens instead of total flock, preventing rooster dilution).
- **Egg Loss Reconciliation**: Reconciles egg loss at collection (harvest loss) vs store-room write-offs (storage loss) without double counting. Uses the equation: `Gross Collected - Harvest Loss = Net Placed in Storage; Net Placed - Sold - Storage Loss = Unsold Stock`.

## 🧪 Testing Guidelines & Gotchas

Run the E2E suite via Playwright:
```bash
# Local Dev Server (Targeting Port 8089)
node tests/e2e.js

# Production / Tailscale Target using OCI credentials:
BASE_URL=http://100.68.227.114:8089 \
E2E_USERNAME=kelvitz \
E2E_PASSWORD=your_password \
node tests/e2e.js
```

### Critical Testing Gotchas
1. **Authentication State Detection**:
   - Do **NOT** detect authentication state using UI selectors like `#nav-dashboard` or `.view-card`. These elements exist in the static HTML structure and are visible immediately before JS evaluation, leading to false "already logged in" state detection.
   - **Fix**: Query `/api/auth/me` directly using `page.evaluate` to retrieve session status from the API.
2. **Network Connection Latency during Simulation**:
   - The 60-day lifecycle simulator (`simulateLifecycle`) performs 90+ sequential POST requests to save daily logs and transactions. Over Tailscale VPN connections, this sequential save process takes between 3 to 10 seconds.
   - Do **NOT** use hardcoded sleeps like `sleep(5000)` to wait for simulation completion.
   - **Fix**: Implement a polling loop that queries `/api/logs/:bid` until the log count reaches 60 before proceeding.
3. **Explicit Cockpit Updates**:
   - When switching batches (e.g. from Kenchic back to ISA Brown), the cockpit view `#view-batch-cockpit` is already visible.
   - Do **NOT** just wait for `#view-batch-cockpit` to load.
   - **Fix**: Use `page.waitForSelector('.cockpit-header h2:has-text("...")')` matching the expected active flock name to guarantee the UI has finished re-rendering the new batch data.
